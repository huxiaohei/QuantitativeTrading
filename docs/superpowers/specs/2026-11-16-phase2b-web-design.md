# 子阶段 2B 设计：网页和登录

日期：2026-11-16。状态：用户已确认（"确认、出计划"；地址用子域名 quant.huxiaohei.online）。
上位文档：`docs/superpowers/specs/2026-11-13-phase2-multiuser-service-design.md`（下称"总设计"）。
本文只写总设计没有定下来的部分；与总设计冲突时以总设计为准，除非本文明确写了"改动"。

标记：【用户】＝用户说过或选过的；【总设计】＝总设计里已确认的；【我的判断】＝本文作者定的，用户审阅时可以改。

## 1. 意图

让用户邀请的家人朋友不用命令行，自己在网页上完成全部事情：注册、选策略、录入自己的持仓和成交、看信号。
2A 已经把每晚运行、两本账、信号、邮件做完，现在只有用户本人能通过 SSH 上的管理命令使用。【总设计】

## 2. 目标

1. 被邀请的人凭邀请码用邮箱注册、验证邮箱、登录、找回密码。【总设计】
2. 使用者在网页上完成 2A 管理命令能做的所有"自己的事"：订阅与改参数、手动账的各种录入与作废、查看两本账、信号、交易日志、设置。【总设计】
3. 管理员（用户本人）在网页上发邀请码、停用账号、看每晚运行记录、触发重跑。【总设计】
4. 网页地址 `https://quant.huxiaohei.online`，正式证书，自动续期。【用户：已购买域名 huxiaohei.online，子域名 quant 已解析到服务器 43.128.130.82，已放开 80/443】
5. 邮件里带上去网页的链接。【总设计 7.9】
6. 手机浏览器上能正常使用。【总设计】

## 3. 不做

- 公开注册（开关存在，固定为邀请码）、支付、套餐限额。【总设计】
- 使用者在网页上跑回测。【总设计】
- 第三方登录（微信、Google 等）、两步验证、修改登录邮箱、使用者自助注销账号。【我的判断：几个熟人用不上；注销由管理员停用账号代替】
- 管理员在网页上查看或修改别人的账本。【总设计】
- 单页应用、前端构建工具、手机 App。【总设计】
- 英文界面。

## 4. 即使跑通也算失败

- 使用者甲通过任何页面或接口读到或改到使用者乙的订阅、账本、信号、日志。【总设计】
- 登录密码明文保存或出现在日志、邮件、报错页面里。【总设计】
- 页面或邮件出现"建议买入""推荐"这类措辞；只能用"信号""提示""按你设定的规则计算"。【原约束】
- 网页层里出现业务规则（校验、账本计算、信号状态变化）。这些只能在 `qt/service/`，网页和命令行调用同一套函数，两边结果必须一致。【总设计 7.2】
- 登录页、找回密码页能被用来探测"某个邮箱是否注册过"。【我的判断】
- 注册验证邮件要等几十分钟才到（现在发件箱每 30 分钟才补发一次）。【我的判断】

## 5. 约束

- 沿用 2A 的全部工程约束：函数参数都带类型标记；ruff、pyright strict、pytest 零告警，不用任何忽略标记；`./scripts/check.sh` 是唯一的合格标准；测试用真实的 PostgreSQL 16。
- 密钥、数据库密码、SMTP 授权码只在服务器的 `.env` 里，由用户自己填。【总设计】
- 页面不加载任何第三方资源（字体、脚本、统计）。【我的判断：隐私，也避免境内访问不稳】
- 服务器 2 核 3.6G，与每晚任务同机。网页服务不做任何耗时计算，不直接跑每日任务。

## 6. 做法

### 6.1 考虑过的做法

整体做法在总设计里已选定：单体服务、服务端渲染页面（FastAPI + Jinja2 模板 + 少量 HTMX，无前端构建）。【用户】
本阶段剩下的选择都是实现层面的，逐项如下，均为【我的判断】：

| 选择 | 定为 | 没选的 | 原因 |
|---|---|---|---|
| 反向代理与证书 | Caddy 容器，自动向 Let's Encrypt 申请和续期 | Nginx + certbot | Caddy 配置只有几行，续期不需要另起定时任务 |
| 登录状态存哪 | 数据库表 `web_sessions` | 签名 Cookie；Redis | 签名 Cookie 无法单独作废（改密码、停用账号要立刻踢下线）；不为此多加一个 Redis |
| 频率限制存哪 | 数据库表 `rate_events` | 进程内存；Redis | 进程重启不丢，量很小 |
| 密码哈希 | argon2id（`argon2-cffi`） | bcrypt | 总设计指定 argon2 一类 |
| 页面交互 | 普通表单提交后跳转；只有"录入前预览费用"等一两处用 HTMX | 全站 HTMX | 表单加跳转在手机上最稳，也最好测 |
| 重跑怎么触发 | 网页写一条请求记录，worker 发现后执行 | 网页进程里直接跑 | 每日任务要跑几十分钟，且有全局锁，不能放在一次网页请求里 |
| 网页怎么拿行情 | 网页进程内缓存一份行情面板，每晚运行完成后重建 | 每次请求现算；另建一套轻量行情 | 手动账的查看和录入必须走 2A 的同一套函数才能与命令行结果一致；每次现算要 7 秒以上 |

### 6.2 部署结构

Compose 从三个服务变成五个：

```
互联网 ──80/443──> proxy (Caddy) ──> web (FastAPI, uvicorn, 只在容器网络内监听 8000)
                                        │
            worker（每晚任务，不变）──> db (PostgreSQL) <──┘
            migrate（一次性）
```

- `web` 与 `worker` 用同一个镜像、同一份配置和 `.env`、同一个 `data/`（只读挂载）。
- `proxy` 只做三件事：证书、把 80 跳到 443、转发到 `web` 并带上真实来访 IP。`web` 只信任来自 `proxy` 的这个头。
- `.env` 新增 `QT_BASE_URL`（如 `https://quant.huxiaohei.online`）。站点域名从它得出；页面和邮件里的所有链接都由它拼出。以后换成子域名只改这一处。
  `worker` 也要读它（信号邮件里的链接）。没设置时 worker 照常运行，邮件里不带链接。
- 镜像里要带上 `docs/concepts.md`；`reports/` 以只读方式挂载给 `web`。
- 本机开发：`QT_BASE_URL=http://localhost:8000`，不启动 `proxy`。只有当地址是 `http://localhost` 或 `http://127.0.0.1` 时才允许 Cookie 不带 `Secure`；其他任何 http 地址启动时直接报错退出。
- 安全响应头由 `web` 统一加：HSTS、`Content-Security-Policy: default-src 'self'`、禁止被嵌入框架、`Referrer-Policy: same-origin`（重置链接带令牌，不能随 Referer 泄露）。

### 6.3 代码划分

- `qt/web/`：路由、表单解析、权限检查、模板。**不含业务规则。**
- `qt/service/auth.py`（新）：注册、验证邮箱、登录、会话、改密码、找回密码、邀请码、频率限制。不引用 FastAPI。
- `qt/service/views.py`（新）：各页面需要的只读查询（总览、账本、信号列表等），全部形如 `(s, user_id, …)`。命令行里已有的同类展示逻辑搬到这里，命令行改为调用它，保证网页和命令行显示同一份数据。
- 写操作全部调用 2A 已有的函数（`accounts.py`、`manual_ops.py`），不新写一份。
- 现在写在命令行层里的两条业务规则要搬进 `qt/service/`，命令行和网页都调用它：参数修改的生效日
  （`admin_cli._next_unprocessed_day`）、订阅起始日的规则（`admin_cli._start_day`）。
- **行情**：手动账的查看与录入需要行情面板（现在命令行每次调用都用 `build_panel` 现建，约 7 秒）。
  网页进程启动后第一次用到时建一份并缓存，发现有新的已完成每日运行时重建；建的过程不能卡住其他请求。
  uvicorn 只开 1 个进程。实施的第一步先量这份面板在容器里占多少内存：超过 800MB 就改成
  "只为当前账本涉及的股票建面板"，并在计划里写明；不允许为网页另写一套计算口径。
- 模板在 `qt/web/templates/`，静态文件（一份 CSS、一份随代码提交的 HTMX）在 `qt/web/static/`。

### 6.5 账号规则

**注册**
- 填邮箱、密码、邀请码，勾选同意《使用条款与风险提示》。密码至少 10 位，不做"必须含大小写符号"的要求，但拒绝与邮箱相同的密码。
- 一个邀请码只能注册一个账号，默认 14 天过期，管理员可提前作废。
- 注册提交后**不自动登录**，一律显示"请去邮箱点验证链接"。点了验证链接后去登录页登录。
  邮箱没验证就登录：密码正确时显示"请先验证邮箱"并可重发验证邮件，不建立会话。所以未验证的账号做不了任何事。【总设计 7.11】
- 邮箱已被注册时：页面显示完全相同的"请查收邮件"，并给该邮箱发一封"有人尝试用你的邮箱注册"的提醒；邀请码不消耗。
  （不自动登录正是为了让这两种情况在页面上看不出区别。）
- 记录同意条款的时间和版本。条款版本变了，下次登录先显示新条款，同意后才能继续。

**登录与会话**
- 登录失败一律提示"邮箱或密码不正确"。
- 会话 30 天内有活动则顺延，Cookie 名 `__Host-qt_session`，`HttpOnly`、`Secure`、`SameSite=Lax`。
- 退出删除该会话；改密码、重置密码、账号被停用时删除该使用者的全部会话。
- 所有 POST 请求必须带与会话绑定的防伪造令牌，并检查 `Origin` 头；不合格返回 403。

**找回密码**
- 无论邮箱是否存在，页面都显示"如果该邮箱已注册，重置邮件已发出"。
- 重置链接 1 小时有效、只能用一次；验证链接 48 小时有效、只能用一次。
- 通过重置链接设好密码，同时视为邮箱已验证（能点开链接就证明邮箱是本人的）。

**已有账号与第一个管理员**
- 2A 用命令行创建的使用者没有密码。他们（包括管理员）走"找回密码"设置密码即可，不提供在命令行里输入密码的命令。
- 第一个管理员：服务器上执行 `qt admin user add --email 邮箱 --admin`（2A 已有），然后在网页上"找回密码"。

**频率限制**（超过后提示"操作太频繁，请稍后再试"）
- 登录失败：同一邮箱 15 分钟 5 次；同一 IP 15 分钟 20 次。
- 注册：同一 IP 每小时 5 次。
- 发验证邮件、重置邮件：同一邮箱每小时 3 封。

**停用账号**
- 管理员停用后：该账号所有会话失效、不能登录、每晚任务跳过它的订阅（不出信号、不发邮件）。恢复后从下一次运行继续，系统账按 2A 的补跑规则补齐。
  （2A 已经不给停用账号发邮件、不让它创建订阅，但每晚仍会推进它的账本并生成信号——`_due_subscriptions` 不看账号状态，这是本阶段要补的。）

### 6.6 账号类邮件必须马上发

- 新增四种邮件：验证邮箱、重置密码、"有人尝试用你的邮箱注册"、密码已修改的通知。
- 仍然走 2A 的发件箱（留痕、去重、失败重试），但网页在提交事务后**立即尝试发送这一封**。
- 发送失败的账号类邮件由**网页进程自己**每 2 分钟补发一次（只管这四种）。不能指望 worker：它是单线程的，
  每晚运行的几十分钟里不会处理发件箱。worker 的补发间隔和范围不变；两边同时取同一封时用行锁避免重复发送。
- 等待页面上有"重新发送"按钮（受频率限制）。
- 邮件里不出现密码；重置和验证邮件写明有效期，以及"如果不是你本人操作，忽略即可"。

### 6.7 权限与隔离（硬性要求）

- 当前使用者只从会话得出，**绝不**从网址或表单里读 `user_id`。
- 网址里出现的订阅、流水、信号等编号，一律用 2A 的 `(s, user_id, …)` 查询函数取，取不到就是 404（不用 403，不泄露"存在但不是你的"）。
- 管理员页面要求 `is_admin`；管理员页面里没有任何能看别人账本、信号、日志内容的路由。使用者列表只显示邮箱、状态、注册时间、是否验证、订阅状态。
- **必须有的自动化测试：**
  1. 每条路由都要在一张表里登记为"公开 / 需登录 / 需管理员"三类之一；有路由没登记，测试失败。
  2. 对每条带编号的"需登录"路由：甲登录后用乙的编号访问，GET 得 404，POST 得 404 且数据库里乙的数据没有任何变化。
  3. 未登录访问"需登录"路由跳到登录页；普通使用者访问"需管理员"路由得 404。
  4. POST 不带或带错防伪造令牌得 403。

### 6.8 页面

导航（登录后）：总览 · 信号 · 手动账 · 系统账 · 策略 · 日志 · 设置 ·（管理员另有"管理"）。手机上导航折叠成一行可横向滑动。

| 页面 | 内容 | 写操作 |
|---|---|---|
| 总览 | 最近一次运行的状态与日期（数据异常那天显示"今日数据异常，未出信号"）；今天的信号；两本账的净值、现金、持仓市值 | 无 |
| 信号 | 待处理的信号在最上；历史信号及状态；被否决的候选及原因 | 买入/卖出信号上有"按此信号录入"，带出股票、方向、数量，价格和日期由使用者填 |
| 手动账 | 持仓（成本、现价、盈亏、止损位、止盈位）、现金、流水 | 录入买入/卖出、录入已有持仓、入金、出金、作废一条流水 |
| 系统账 | 持仓、流水 | 无（只读） |
| 策略 | 当前订阅的状态；每个参数的含义（取自 `docs/concepts.md`）、当前值、默认值 | 创建订阅（起始资金、起始日）、改参数、暂停、恢复、关闭 |

| 设置 | 邮箱、周报开关、放弃提醒开关 | 改两个邮件开关、改密码、退出所有设备 |
| 管理·邀请码 | 列表及状态 | 生成（带备注）、作废 |
| 管理·使用者 | 邮箱、状态、注册时间 | 停用、恢复 |
| 管理·运行 | 最近的每日运行、状态、失败原因全文、批量行情使用情况、发件箱待发与失败数 | "立即重试"；把发送失败的邮件重新排队 |
| 公开页 | 登录、注册、找回密码、《使用条款与风险提示》 | — |

细节：
- 所有写操作成功后跳转回列表页并显示一行结果；失败时回到原表单，保留已填内容，在出错的字段旁显示 2A 业务函数给出的中文原因。
- 作废、关闭订阅、停用账号这类操作先进一个确认页再执行。
- 改参数页明确写"修改参数后没有对应的回测结果可看"，并显示这次修改从哪一天起生效（用搬进 `qt/service/` 的那条规则）。
- 参数说明：`docs/concepts.md` 是按概念写的，和参数不是一一对应。为每个可改参数新写一两句说明
  （放在代码里与参数标签同一处，命令行也能用），并链接到站内的"概念说明"页（由 `concepts.md` 渲染）。
  新写的说明不得出现任何"建议取值"之类的话，只解释含义和调大调小的效果。
- 默认参数的回测报告：配置项 `web.report_file` 指向 `reports/` 下的一个文件，以只读方式提供给已登录使用者；
  没配置或文件不存在就不显示链接。
- 历史订阅：策略页列出已关闭的订阅。两本账、信号、日志各页默认看当前订阅，可切换到历史订阅只读查看；
  订阅编号因此会出现在网址里，按 6.7 的规则校验归属。【总设计 7.4】
- 手动账只接受沪深主板股票（2A 现状），录入页写明这一点。
- 每个页面底部固定一行："以上内容是按你设定的规则计算的结果，不构成投资建议。"
- 金额、日期、涨跌颜色（红涨绿跌）按国内习惯。表格在窄屏上可横向滚动，不隐藏列。

### 6.9 重跑

不提供"任选一天重跑"：已完成的那天重跑什么也不会变，而对很早的日子重跑会把旧信号当新邮件发出去。
只提供一个按钮"立即重试"：

- 用途：某晚数据失败后，不想等 worker 的 30 分钟重试间隔。只有当存在未完成的交易日
  （数据失败、运行失败、或漏跑）时按钮才可用。
- 管理员点击后写入 `rerun_requests`；worker 空闲时每分钟看一次，有请求就立刻执行它本来到点才做的那次
  补跑（2A 的 `catch_up`，通知与否完全按 2A 的既有规则），结果写回请求记录。
- 每晚运行进行中时请求会等到运行结束；页面上写明"正在运行，结束后处理"。

### 6.10 留痕

2A 的 `audit_log` 增加记录：注册、登录成功与失败、退出、改密码、重置密码、同意条款、生成与作废邀请码、停用与恢复账号、请求重跑。
同时解决 2A 留下的一项：记录里要能分清"使用者本人在网页上做的"和"管理员在命令行替他做的"。
做法：`audit_log` 加 `channel` 列；`accounts` 和 `manual_ops` 的写函数加一个"操作来源"参数
（操作人、渠道），命令行传"命令行 + 无登录操作人"，网页传"网页 + 当前使用者"。已有记录的渠道填 `cli`。

## 9. 已知风险

- **新域名 + 新发信地址，邮件容易进垃圾箱。** 上线后先用几个常见邮箱（QQ、163、Gmail）各试一封。
- 服务器在境外，境内访问偶尔会慢；页面保持很轻（无外部资源、无大脚本）。
- `.online` 域名一年后续费价格通常比首年高，记得留意到期日（2027-11-16）。
