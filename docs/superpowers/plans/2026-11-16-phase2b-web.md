# 子阶段 2B：网页和登录 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 2A 的每日信号服务加上网页：邀请码注册、邮箱验证、登录、找回密码，使用者自助完成订阅、手动账录入、查看两本账与信号，管理员发邀请码、停用账号、看运行记录；上线到 `https://quant.huxiaohei.online`。

**Architecture:** 同一个镜像新增 `web` 服务（FastAPI + Jinja2 服务端渲染，少量 HTMX），前面放 Caddy 反向代理自动签发证书。账号逻辑在 `qt/service/auth.py`，页面的只读查询在 `qt/service/views.py`，写操作全部调用 2A 已有的 `qt/service/` 函数；`qt/web/` 只做表单解析、权限检查、渲染。

**Tech Stack:** Python 3.12、FastAPI、uvicorn、Jinja2、HTMX（随代码提交的单文件）、argon2-cffi、SQLAlchemy 2 + Alembic + PostgreSQL 16、Caddy 2、Docker Compose、pytest（FastAPI TestClient + 真实 PostgreSQL）。

**Spec:** `docs/superpowers/specs/2026-11-16-phase2b-web-design.md`（下称"设计"）；上位文档 `docs/superpowers/specs/2026-11-13-phase2-multiuser-service-design.md`。两份都要读。

## Global Constraints

- 所有函数参数和返回值带类型标记；ruff、ruff format、pyright strict、pytest 零告警；不得使用 `# type: ignore`、`# noqa`、`# pyright: ignore`、`# fmt: skip`。缺类型信息的第三方库在边界处封装成有类型的小函数。
- 合格标准只有一个：`./scripts/check.sh` 退出码 0。每个任务提交前都要跑。
- 测试用真实 PostgreSQL 16（`tests/conftest.py` 的 `db_engine` / 会话夹具），不用 SQLite，不 mock 数据库。
- 界面、报错、邮件、提交说明、代码注释和文档字符串都用中文。
- 措辞：只用"信号""提示""按你设定的规则计算"；不得出现"建议买入""推荐""应该买"之类。每个登录后页面底部固定一行"以上内容是按你设定的规则计算的结果，不构成投资建议。"
- `qt/web/` 里不得有业务规则（校验、账本计算、信号状态变化、生效日计算）；`qt/service/` 不得引用 FastAPI / Starlette。
- 当前使用者只从会话得出，绝不从网址、表单、请求头读 `user_id`。网址里的任何编号都用 `qt.db.repo` 的 `(s, user_id, …)` 函数取，`NotFoundError` → 404。
- 密码、会话令牌、邮件令牌的原文不得写入日志、数据库、报错页面；数据库只存哈希。
- 页面不加载任何第三方资源。
- AKShare 只在 `src/qt/data/akshare_source.py` 里调用；不得破坏性地触碰 `data/`。
- 不读取、不修改 `.env`（只改 `.env.example`）；不填任何 SMTP 授权码。
- 提交：每个任务一个或多个提交，在分支 `phase2b-web` 上；不 amend 别人的提交，不 push，不合并到 `main`。提交说明末尾加 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`。
- 网页地址只来自环境变量 `QT_BASE_URL`；代码和模板里不得写死域名。

## Review Focus

1. **邮箱大小写与空白**：注册用 `Foo@Example.com `，登录用 `foo@example.com` → 视为同一个账号（2A 已约定邮箱小写存放）；频率限制的键也用规范化后的邮箱。测试在任务 5。
2. **链接被点两次或被邮箱安全扫描预先访问**：验证链接、重置链接的 GET 只显示页面、不消耗令牌；真正消耗在 POST。第二次使用给出明确的"链接已使用或已过期"页面而不是 500。测试在任务 7。
3. **两个标签页 / 重复提交**：录入成交的表单被连点两次 → 第二次由 2A 的账本校验拒绝或得到与第一次相同的明确报错，不产生两条流水也不出 500。测试在任务 11。
4. **会话过期时提交了填好的表单**：POST 时会话已失效 → 跳到登录页并提示"登录已过期，请重新登录"，不是 403 也不是 500。测试在任务 7。
5. **还没有任何每日运行记录、还没有订阅的新使用者**：总览、信号、两本账、日志各页都要能打开并显示"还没有…"的说明和下一步的链接，不出 500。测试在任务 9、10。

### Task 5: 账号服务 `qt/service/auth.py`

**Files:**
- Create: `src/qt/service/auth.py`
- Modify: `src/qt/service/errors.py`、`src/qt/db/admin_repo.py`
- Test: `tests/service/test_auth.py`

**Interfaces — Consumes:** Task 1 的模型与 `WebConfig`；Task 2 的 `Actor`。

**Interfaces — Produces（全部第一个参数 `s: Session`，时间一律由调用方传入 `now: datetime`，便于测试）:**
- 错误类（加在 `errors.py`）：`AuthError(ValidationError)`；`RateLimitedError(AuthError)`（消息固定"操作太频繁，请稍后再试"）；`EmailNotVerifiedError(AuthError)`（带 `user_id`）。
- `normalize_email(text: str) -> str`：去首尾空白、转小写。
- `hash_password(plain: str) -> str` / `verify_password(hashed: str | None, plain: str) -> bool`（argon2id；`hashed is None` 返回假且耗时与真实校验同量级）。
- `check_password_rules(email: str, plain: str, min_length: int) -> None`：不足长度、与邮箱相同 → `AuthError`。
- `rate_check(s, key: str, limit: int, window: timedelta, now) -> None`（超限抛 `RateLimitedError`）与 `rate_hit(s, key: str, now) -> None`。
- `create_invite(s, admin_id: int, note: str, valid_days: int, now) -> Invite`、`revoke_invite(s, admin_id: int, invite_id: int, now) -> Invite`、`admin_repo.list_invites(s) -> list[Invite]`。
- `register(s, email: str, password: str, invite_code: str, accepted_terms: bool, cfg: WebConfig, ip: str, now) -> RegisterResult`，`RegisterResult(kind: Literal["created","exists"], user_id: int, token: str | None)`：
  - 未勾选条款、邀请码无效/过期/已作废/已使用、密码不合规 → `AuthError`（这些不泄露邮箱是否存在：邀请码与密码先于邮箱查重校验）。
  - 邮箱已存在 → `kind="exists"`，不消耗邀请码，`token=None`。
  - 新建 → 写密码哈希、条款版本与时间，邀请码标记已用，签发 `verify` 令牌并返回原文。
  - 频率：`register-ip:{ip}` 每小时 5 次。
- `issue_email_token(s, user_id: int, kind: Literal["verify","reset"], hours: int, now) -> str`（返回原文，库里只存 SHA-256）；同一使用者同类旧令牌作废。
- `peek_email_token(s, token: str, kind, now) -> int | None`（有效则返回 `user_id`，不消耗）。
- `verify_email(s, token: str, now) -> User | None`（消耗令牌，写 `email_verified_at`）。
- `request_password_reset(s, email: str, cfg: WebConfig, now) -> tuple[User, str] | None`（邮箱不存在或账号停用返回 `None`；频率 `mail:{email}` 每小时 3 封，超限也返回 `None` 而不是报错，避免探测）。
- `reset_password(s, token: str, new_password: str, cfg: WebConfig, now) -> User`（消耗令牌、写新哈希、`email_verified_at` 为空则补上、删除该使用者全部会话）。
- `resend_verification(s, user_id: int, cfg: WebConfig, now) -> str | None`（同一频率键；已验证返回 `None`）。
- `login(s, email: str, password: str, ip: str, user_agent: str, cfg: WebConfig, now) -> LoginResult`，`LoginResult(token: str, session: WebSession, user: User)`：
  - 频率：`login:{email}` 15 分钟 5 次失败、`login-ip:{ip}` 15 分钟 20 次失败；只在失败时计数。
  - 邮箱不存在、密码错、账号停用 → `AuthError("邮箱或密码不正确")`（三者文字完全相同）。
  - 密码正确但邮箱未验证 → `EmailNotVerifiedError`，不建会话。
- `load_session(s, token: str, cfg: WebConfig, now) -> tuple[WebSession, User] | None`（过期、使用者停用返回 `None`；有效则把 `last_seen_at`、`expires_at` 顺延，最多每 5 分钟写一次库）。
- `logout(s, token: str) -> None`、`logout_all(s, user_id: int) -> int`。
- `change_password(s, user_id: int, current: str, new: str, cfg: WebConfig, keep_session_id: int, now) -> None`（当前密码错 → `AuthError`；删除除 `keep_session_id` 外的全部会话）。
- `needs_terms(user: User, cfg: WebConfig) -> bool`、`accept_terms(s, user_id: int, cfg: WebConfig, now, actor: Actor) -> None`。
- `set_user_status(s, admin_id: int, user_id: int, status: Literal["active","disabled"], now) -> User`（停用时删除其全部会话；不能停用自己 → `AuthError`）。
- `purge_expired(s, now) -> int`（清理过期的会话、令牌、超过 2 天的频率记录）。
- 以上每个改动数据的操作都写一条审计（设计 6.10 列出的动作名用英文蛇形，如 `login_ok`、`login_failed`、`register`、`password_reset`）。登录失败的审计 `detail` 里记规范化邮箱和 IP，不记密码。

- [ ] **Step 1:** 写失败的测试，至少覆盖：
  - 密码：哈希后能验证；`verify_password(None, "x")` 为假；长度 9 被拒、10 通过；与邮箱相同被拒。
